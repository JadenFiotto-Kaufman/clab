# The clab format

Generated by `clab describe --markdown` from the code; a test fails when this file and the code disagree. A document is one JSON object that declares a complete experiment; `clab run DOC` runs it. Its JSON Schema is `schema.json` (`clab schema`).

## Root keys

| key | holds |
| --- | --- |
| `description` | what the experiment is, in prose |
| `model` | the checkpoint, and how to load it |
| `data` | each dataset by name |
| `sites` | named locations, referenced by `site` |
| `interventions` | named bundles of writes and reads, pulled into a step by `interventions` |
| `featurizers` | named spaces a read or write happens in |
| `steps` | what runs, in order |
| `saves` | the values that come home, by name |

### `model`

- `key: str`
- `revision: str`
- `dtype: one of 'float32', 'float16', 'bfloat16' = 'float32'`

The pinned checkpoint: `key`, `revision` and `dtype` (torch's spelling). Every other key goes to the
engine's loader untouched (`attn_implementation`, `device_map`, ...), and a loader refuses what it cannot
honor. The attention interior needs `attn_implementation: "eager"`.

### `data.<name>`

- `path: str or null = None`
- `rows: list of dict or null = None`
- `hf: str or null = None`
- `revision: str or null = None`
- `split: str or null = None`
- `take: int or null = None`

A dataset: `path` is `data/<path>.json` under the corpus root, or `rows` are inline, or `hf` names a
pinned hub dataset (`revision`, `take` rows of `split`). `split` keeps the rows of that split.

### `sites.<name>`, or a `site` inline

- `component: str`
- `layers: int or one of 'all' or a sweep or null = None`
- `select: object of list of int or a sweep or null = None`

A component, narrowed: `layers` (an int, or `"all"`: one value, the layer axis first) on a block's
component, and `select` (`{<axis>: [indices]}`) on the axes it publishes besides its rows and tokens.

### A write or a read

- `site: str or site`
- `pos: int or pos or a sweep`
- `ops: list of op = []`

A write or a read: the `site` it lands on (a declared name, or one inline), the positions `pos` names
there, and the `ops` it runs on that selection. Several writes at one site compose in listed order on one
copy of the value; a read at a written site observes the writes.

### An op in a write or a read

- `op: str`
- `featurizer: str or null = None`
- `select: object of list of int or a sweep or null = None`

An op inside a read or a write: `{"op": <name>, ...its arguments}` (see Ops). `featurizer` makes any op
run on the value's coordinates in that featurizer's space, the change written back; `select`
(`{"features": [indices]}`) narrows it to some of them. On the `featurizer` op it names the featurizer
the op calls.

### `pos`

- `frame: int or list of int or one of 'generated', 'all', 'eos' or a sweep = 0`
- `scope: scope or null = None`
- `index: int or list of int or one of 'all' or a sweep = 'all'`

`pos` is three stages of narrowing: `frame` picks forward calls, `scope` picks text within their tokens,
`index` picks positions within that.

```
pos   := int                                   # shorthand: {"frame": 0, "index": int}
       | {"frame"?: frame, "scope"?: scope, "index"?: index}
frame := int | [start, stop] | "generated" | "all" | "eos"         # default 0
scope := {"column" | "text": one or a list, "occurrence"?: selector, "strip"?: bool}
       | {"turn": "<role>", "occurrence"?: selector}
index := int | [start, stop] | "all"                               # default "all"
selector := int | [start, stop] | "all"                            # occurrence's; default 0
```

**frame**: 0 is the prefill, the only call a `forward` step has; k >= 1 is decode call k; a negative k
counts from the row's last call; a span is half-open; `"generated"` is every decode call, `"all"` the
prefill and every decode call (in a `forward`, its one call: so a named intervention written at `"all"`
is on in every call of whichever step names it), `"eos"` the call where the row stopped (the one that
chose its EOS). A
position is where an input token sits, in a forward and in a generation alike: the prefill holds every
prompt token, its last position the distribution over generated token 0; under the cache decode call k
holds one position, generated token k-1 (its input), and its logits are the distribution over token k. A
row's calls end with the one that chose its last token, so the token it stopped on is never an input. The
prompt's tokens are the row's tokens that are not special (BOS is never one) and not padding; a
generation's prefill computes the head (`lm_head_output`, `logits`) at its last position only, so there
call 0 holds that one position.

**scope** (default: every token the frame selected): `column` and `text` locate text in the selected
calls' tokens, in the prompt by the tokenizer's offsets and in the generated tokens by decoding growing
prefixes. A list of columns or texts locates every occurrence of each. Occurrences are ordered by where
they end, then where they start: where an occurrence becomes known and where index -1 lands, so a write
found online, a read and the run record count them alike (`b` inside `abc` comes before it). `occurrence`
(default 0, the first of any) picks which of those occurrences among the tokens the
scope is, with the selector `frame` and `index` use; the scope is the tokens of the picked ones, in order
(their union where occurrences of different texts overlap), and `strip` strips each text of surrounding
whitespace first. The prompt and the generated
tokens are searched apart, so a text straddling the boundary is not found; and a row's last generated
token is never an input to any call, so a word ending on it is `alignment_missing` (with
`max_new_tokens: 1` a scope in the generated tokens never matches). `turn` is a role of the chat, in
call 0 only: its messages are its occurrences, in order (`{"turn": "user", "occurrence": 1}` is the second
user message, `"all"` every one of them); a role the row has no message of is refused by name.

**index** (default `"all"`): an int counts the scope's tokens (negative from the end), a span is
half-open. It counts over the tokens of every call the frame selected, in order: `{"frame": [0, 3],
"index": -1}` is one position, the last token of call 2, the same as `{"frame": 2, "index": -1}`.

A record is rectangular (the same width on every row, `(rows, pos, ...)`) when its frame is one call or
a span of calls, its index is an int or a span whose ends count from the same side, and a `column`/`text`
scope, if it has one, is one occurrence (an int) in the prefill; otherwise it is ragged, one entry per
token, `{values, row, tok}`, `tok` the position. In the prefill (`frame: 0`) an occurrence a row does not
have, or a rectangular index that does not fit, is refused by name before any forward: the data decided.
Anywhere else it is a result, as is a call the row never reached: the row is `alignment_missing`, NaN in
a rectangular read and absent from a ragged one.

### `interventions.<name>`

- `writes: object of write or read = {}`
- `reads: object of write or read = {}`

A bundle of `writes` and `reads` (each by name), pulled into a step by `"interventions": "<name>"` or a
list of names. Its names resolve where a step pulls it in. A write's operand may name one of the bundle's
own reads by its bare name (`"with": "premix"`, a cross-site adapter's input): it means that read of
whichever step pulls the bundle in. `<a step>.<one of the bundle's reads>` is refused, since pulled into
another step it would still mean that step's read. A write's operand from its own step's reads is served
in a forward; inside a generate it is not yet (a cross-site adapter in a generation is on the roadmap).

## Step kinds

Each entry of `steps` is `{"kind": <kind>, ...fields}`.

### `forward`

- `input: str`
- `writes: object of write or read = {}`
- `reads: object of write or read = {}`
- `interventions: str or list of str or null = None`

One forward over every row of a dataset input. `input` is `<dataset>.<column>` or
`<dataset>.<column>[i]`, a text or a chat; `writes` land where they name before anything later reads them;
each read binds `<step>.<read>`; `interventions` pulls named bundles of writes and reads in, in listed
order, before the step's own.

A chat input (a list of `{"role", "content"}` messages) is rendered through the checkpoint's own chat
template without a generation prompt, so the rendered prompt ends with the template's close of the last
message (`[/INST]` on Llama-2-style templates): `pos: -1` with no scope is that close's last token, and
`{"scope": {"turn": "user", "occurrence": 1}}` names the second user message's own tokens.

Rows run in consecutive batches of the run's batch size, each padded on the left to the input's longest
row, with position ids that count real tokens. A row's numbers then do not depend on which rows share its
batch, but they do depend on the batch's shape: a trailing partial batch is a smaller matrix, and can
differ in the last bits. Results reproduce to the bit at a fixed batch size.

### `generate`

- `input: str`
- `writes: object of write or read = {}`
- `reads: object of write or read = {}`
- `interventions: str or list of str or null = None`

Generation from every row of a dataset input. It owns `input`, `writes`, `reads` and `interventions`, as
a forward does; every other key goes to the engine's `generate` as-is (`max_new_tokens`, `min_new_tokens`,
`do_sample`, ...), and may sweep. Its reads and writes name forward calls by `pos`'s `frame`: the
prefill, and the decode calls, each at its one position. A write at decode call k takes effect from
generated token k on, through the cache. A write lands as its call runs, so beyond the prefill what it
selects is known by then: without a scope, a call, a span of calls or `generated` with an index counted
from their start (or -1 of a single call), or the prefill with them and index `all`; with a `column` or
`text` scope, decode calls only (a call, a span from 1 or `generated`), index -1 and an occurrence
counted from the first. A scoped write is found online, decoding the inputs fed so far at each call: it
lands at the call fed the last token of each occurrence it picks, as that occurrence appears (its
earlier tokens were fed before the text was there to find), and a row with fewer occurrences than it
picks is `alignment_missing`. No write takes `eos` or a frame counted from a row's last call. A row's
calls are what the engine actually generated, up to the
one that chose the row's first EOS: the step's own `eos_token_id` when it gives one, else the id the
engine's generation stops on (its generation config's). The step's own value is the
new token ids, `[rows, new]`; `decode` makes them text. Options that would change the rows or the value
(`num_return_sequences`, `num_beams`, `return_dict_in_generate`, `use_cache`) are refused before anything
runs; any other option is the engine's `generate`'s to accept, and one it rejects fails when the step
runs, naming the step.

Rows run in batches as a forward's do, and reproduce to the bit only at a fixed batch size: the prefill
projects the head at the last position only and every decode call is a `[batch, 1, ...]` matmul, so
batch sizes 4 and 2 already differ by about 1e-7 at call 0.

### `op`

- `op: str`
- `of: str`

An op over a value earlier steps produced: `of` names it, and the op's arguments sit beside it (see
Ops). The step's value is the op's result; a step holds exactly one op, and chaining is the next step.

### `fit`

- `train: list of str`
- `objective: object of float or a sweep`
- `epochs: int or a sweep`
- `batch_size: int or a sweep`
- `seed: int or a sweep`
- `optimizer: optimizer`
- `steps: object of step`
- `early_stop: early_stop or null = None`
- `eval: object of object of str = {}`

Train the featurizers `train` names, inside the run, through the frozen model.

Each trained featurizer is made at the fit's start (drawn from its own `seed`, else the fit's), and the
optimizer over its trainable tensors with it. Each epoch sets a gate's temperature, then runs the body
`steps` over minibatches of `batch_size` rows of its datasets, shuffled by a generator seeded with `seed`
and the epoch, with gradients on and gates soft, and steps the optimizer once per minibatch on the
weighted sum `objective` (`{term: weight}`; a term is a body op averaged over every axis, or a trained
featurizer's scalar, `<featurizer>.<scalar>`). Gradients are taken for the featurizers' tensors alone; the
model's weights are never touched. After each optimizer step a featurizer with a constraint is projected
back onto it (an sae's decoder rows to unit norm). After each epoch the body runs over every training row
in scoring mode (gates hard, no gradients): each body op's mean and each trained featurizer's scalar is
that epoch's entry of `<fit>.history.<op>` and `<fit>.history.<featurizer>.<scalar>`, and `early_stop`
is judged on it. The best epoch's featurizer tensors (without `early_stop`, the last's) are restored, and
the body runs once, scored, per named substitution of `eval`, in listed order: `{"held_out": {"train":
"test"}, "train": {}}` runs it with dataset `train` read as `test`, then on the data it trained on. The
body's forwards run in batches of `batch_size`, whatever the run's batch size.

The body is a scope of its own that sees every value produced before the fit; a trained featurizer's
name and `<fit>.<featurizer>` both mean the one being trained, and a value with a row per example it uses
is one it makes. Nothing leaves it except through the fit's members: `<fit>.<featurizer>` the trained
featurizer (saved as its bundle), `<fit>.<eval>.<op>` and `<fit>.<eval>.<step>.<read>` a body value from
the run named `<eval>`, and `<fit>.history.<term>`, `[epochs]`, one entry per epoch run. A sweep over any
of the fit's values (an objective weight, the learning rate) makes the fit, its members and their users a
list of points.

### `fit` blocks

`optimizer`:

- `name: one of 'adamw', 'adam', 'sgd'`
- `lr: float or a sweep`
- `weight_decay: float or a sweep = 0.0`

The fit's optimizer, over the trained featurizers' parameters only.

`early_stop`:

- `metric: str`
- `mode: one of 'max', 'min'`
- `patience: int or a sweep`

End the fit after `patience` epochs without improvement (`mode` max or min) of body op `metric`'s mean,
scored on the training rows after each epoch.

## Derived fields

Fields a document leaves out, which compile (or, for `run`, the engine) fills:

- `Plan`: `document` (the document file the plan was read from; written relative to its corpus root, where data paths and bundles resolve), `compiled` (whether this is the compiled plan), `sweeps` (each sweep axis by label, in axis order), `results` (each saved value by name; a swept one is a dict keyed by coordinate), `run` (how the plan ran, set by `execute`)
- `Data`: `sha256` (the digest of the rows, which a re-materialization must match), `n_rows` (how many rows the dataset has)
- `Access`: `dims` (the layout of what a read binds)
- `Forward`: `at` (the point's index on each sweep axis it varies over), `dataset` (the dataset whose rows the step's values are aligned to)
- `Generate`: `at` (the point's index on each sweep axis it varies over), `dataset` (the dataset whose rows the step's values are aligned to)
- `OpStep`: `at` (the point's index on each sweep axis it varies over), `dataset` (the dataset whose rows the step's values are aligned to), `dims` (the layout of the step's value)
- `Featurizer`: `at` (the point's index on each sweep axis it varies over), `bundle` (the tensors of the bundle `file_path` names, checked against its header), `header` (the header of the bundle `file_path` names, which preflight checks the model's width against)

## Ops

An op runs in three places, always as the same function:

- as a step, `{"kind": "op", "op": "mean", "of": "harvest.acts"}`, over a value earlier steps produced;
- inside a read, `"ops": [...]`, on the gathered selection before its name binds;
- inside a write, `"ops": [...]`, on the live selection at the site; what the last op returns is written back.

Inside a read or write an op sees one batch, so it must act per example: one that aggregates over rows is
refused there (make it a step after the forward).

A row a read beyond the prefill did not reach is missing all the way down: in a rectangular value it is NaN,
every metric and edit of it is NaN, `argmax` and `top_k` give it id -1 (`top_k` NaN probabilities and no
token text). Reductions skip it: `mean` is the mean over the rows that have a value, and `pca` is fitted on them.

Ops come in four groups: **metrics** score each example (one number per row and position: `match` is 0 or
1, and the accuracy is a `mean` step after it); **reductions** remove the rows axis; **edits** keep the
value's layout and change its contents; **transforms** turn each example's value into another of a
different layout (logits from a residual stream, tokens from logits, text from ids).

An argument is filled by a document as its type says: `Value` is a named value or a number; `Tokens` a
dataset column, resolved through the value's own vocabulary: one token per row against logits, or one of a
probe's classes against its scores (a metric scores a `vocab_size` or a `classes` axis); `Featurizer` a
featurizer's name; anything else is a literal. Inside a read or write, `featurizer` and `select` are
arguments of every op: the op runs on the value's coordinates in that featurizer's space (on the features
`{"select": {"features": [...]}}` keeps; an operand is laid out on them) and the change is written back as a
delta, so an op that changes no coordinate changes nothing to the bit. The `featurizer` op calls a featurizer
instead, in one of its kind's modes (`encode` gives the coordinates themselves, `apply` the featurizer's
version of the value). `renormalize`'s reference is the value at the site before the step's writes. Inside a
write, an operand may name a read of the same forward at a site the forward reaches before the write's
(`patched.premix` in `patched`): it is that read's value in this batch, at the read's positions.

### Metrics

| op | arguments | axes | what |
| --- | --- | --- | --- |
| `match` | `expected: Tokens`, `token_form: one of 'spaced', 'bare' = 'spaced'` | needs vocab_size or classes; removes its vocabulary axis | 1 where the most likely token is `expected`, else 0. |
| `logit_diff` | `a: Tokens`, `b: Tokens`, `token_form: one of 'spaced', 'bare' = 'spaced'` | needs vocab_size or classes; removes its vocabulary axis | The logit of `a` less the logit of `b`. |
| `token_prob` | `token: Tokens`, `token_form: one of 'spaced', 'bare' = 'spaced'` | needs vocab_size or classes; removes its vocabulary axis | The probability of `token`. |
| `token_logit` | `token: Tokens`, `token_form: one of 'spaced', 'bare' = 'spaced'` | needs vocab_size or classes; removes its vocabulary axis | The logit of `token`. |
| `cross_entropy` | `target: Tokens`, `token_form: one of 'spaced', 'bare' = 'spaced'` | needs vocab_size or classes; removes its vocabulary axis | The negative log-probability of `target`, in nats. |
| `kl` | `against: Value` | needs vocab_size or classes; removes its vocabulary axis | KL(of ‖ against) between the two next-token distributions, in nats. |
| `js` | `against: Value` | needs vocab_size or classes; removes its vocabulary axis | The Jensen–Shannon divergence between the two distributions, in nats (at most log 2). |

### Reductions

| op | arguments | axes | what |
| --- | --- | --- | --- |
| `mean` | `over: list of str or null = None` | removes the axes `over` names | The mean over the axes `over` names, of the rows that have a value (a missing row is NaN); by default over every axis but the feature axes. |
| `pca` | `k: int` | needs hidden_size; removes layers, rows, entries, pos; adds k | The top-`k` principal directions (`basis`, `[hidden_size, k]`, orthonormal columns, the largest variance first) and the `mean` they are centred on: the bundle a `pca` featurizer loads. |

### Edits

| op | arguments | axes | what |
| --- | --- | --- | --- |
| `swap` | `with: Value` | keeps the layout | Replace the value with `with`, broadcast over its rows and positions. |
| `add` | `with: Value`, `scale: float = 1.0` | keeps the layout | `of + scale * with`. |
| `sub` | `with: Value` | keeps the layout | `of - with`. |
| `scale` | `factor: float` | keeps the layout | `of * factor`. |
| `renormalize` | — | keeps the layout | Each vector rescaled to the norm of `original`'s; inside a write, the value before the site's writes. |
| `normalize` | — | keeps the layout | Each vector divided by its norm. |
| `project_out` | `direction: Value` | keeps the layout | Each vector less its component along `direction`. |

### Transforms

| op | arguments | axes | what |
| --- | --- | --- | --- |
| `readout` | — | needs hidden_size; removes hidden_size; adds vocab_size | The model's own readout of a residual-stream value, its final norm and head (the logit lens). |
| `featurizer` | `featurizer: Featurizer`, `mode: str`, `...` | its mode's (see Featurizer kinds) | `featurizer` called on the value in `mode`, one of its kind's modes, with the mode's own arguments beside (`with`, for a lora's `apply`): `encode` gives its coordinates (a probe's: its scores, one per class), `apply` its version of the value. Its axes depend on an argument: they are the mode's, which the featurizer's kind declares (see Featurizer kinds), and the op declares them as that function. |
| `top_k` | `k: int` | needs vocab_size; removes vocab_size; adds k | The `k` most likely tokens, `{"ids", "probs"}`, most likely first; as a step, its value also holds their `tokens`, decoded. |
| `argmax` | — | needs vocab_size; removes vocab_size | The id of the most likely token (-1 where the value is missing). |
| `decode` | `tokens: bool = False` | needs new; removes new | Each row's generated ids as text, stopped before the row's first EOS (the id its generation stops on); with `tokens`, as its token strings. |

## Components

The locations clab allows: what each component means, its layout, and what narrows it.

A component's name is nnterp's name for the same value, and its `dims` are
nnterp's layout of it (`batch` first, the token axis named `seq`, or `query` on
an attention pattern). `per_layer` says it is a block's value, so a site names
its `layers`. A site's `select` narrows any axis of its `dims` but the rows and the token axis (`batch`,
`seq`, `query`), which `pos` addresses. `stream` marks the residual-stream values `readout` may project.

A selection of a component (what a read binds, and what a write's ops see) is
laid out `(rows, pos, *the remaining axes in order)`: a `layers` axis comes
first under `layers: "all"`, and ragged positions give `entries` (one per
token) in place of `rows` and `pos`. How an engine reaches a component is that
engine's business; the name says only what the value is.

| component | dims | narrowed by | meaning |
| --- | --- | --- | --- |
| `token_embeddings` | batch, seq, hidden_size | hidden_size | the embedding module's output |
| `layer_input` | batch, seq, hidden_size | layers, hidden_size | the residual stream entering block i |
| `attention_norm_output` | batch, seq, hidden_size | layers, hidden_size | the normed stream the attention is called with |
| `attention_queries` | batch, num_heads, seq, qk_head_dim | layers, num_heads, qk_head_dim | queries after projection, head split and RoPE |
| `attention_keys` | batch, num_kv_heads, seq, qk_head_dim | layers, num_kv_heads, qk_head_dim | keys, before repeat_kv |
| `attention_values` | batch, num_kv_heads, seq, head_dim | layers, num_kv_heads, head_dim | values, before repeat_kv |
| `attention_scores` | batch, num_heads, query, key | layers, num_heads, key | scaled, masked scores entering the softmax |
| `attention_probabilities` | batch, num_heads, query, key | layers, num_heads, key | the pattern the values are mixed with |
| `attention_head_outputs` | batch, seq, num_heads, head_dim | layers, num_heads, head_dim | each head's output, before the output projection |
| `attention_premix` | batch, seq, num_heads, head_dim | layers, num_heads, head_dim | every head's result as the output projection takes it |
| `attention_output` | batch, seq, hidden_size | layers, hidden_size | what attention adds to the stream |
| `layer_mid` | batch, seq, hidden_size | layers, hidden_size | the stream between the sublayers |
| `mlp_norm_output` | batch, seq, hidden_size | layers, hidden_size | the normed stream entering the MLP |
| `mlp_input` | batch, seq, hidden_size | layers, hidden_size | what the MLP is called with |
| `mlp_activation` | batch, seq, intermediate_size | layers, intermediate_size | act(gate_proj x) on a gated MLP, act(up_proj x) on a plain one |
| `mlp_neurons` | batch, seq, intermediate_size | layers, intermediate_size | what the down projection sums |
| `mlp_output` | batch, seq, hidden_size | layers, hidden_size | what the MLP adds to the stream |
| `layer_output` | batch, seq, hidden_size | layers, hidden_size | the residual stream leaving block i |
| `final_norm_output` | batch, seq, hidden_size | hidden_size | the final norm's output, what the head projects |
| `lm_head_output` | batch, seq, vocab_size | vocab_size | the head's own projection |
| `logits` | batch, seq, vocab_size | vocab_size | what the model returns, after any softcap |

## Featurizer kinds

Featurizer kinds: the fields each kind takes, what an instance is, and how a value moves in and out of its space.

A featurizer is a space a read or write happens in, or a function on a value. Its kind's signature is its
contract: the document fields it takes, with `width` (the feature width of the sites it is used at), `bundle`
and `header` (the tensors and header of the bundle its `file_path` names) supplied by the run, and for a probe
`labels` (its class list). An instance holds plain tensors, never an `nn.Module`, made where the model is: a
declared featurizer before the run's first step, one a fit trains at the fit's start. It is drawn from its
`seed` (else the seed of the fit that trains it, else 0), or loaded from its bundle, which compile reads into
the plan and checks key by key against the document; a loaded one is fixed. It is called by the `featurizer`
op in one of its kind's modes: `encode` gives its coordinates of a value `h` (the last axis becomes the
kind's axis: `features`, or a probe's `classes`), and `apply` its version of `h` in `h`'s own layout (a
subspace's projection, a dictionary's reconstruction, a gate's masked value, an adapter's adapted value). An
edit op in its space runs on its coordinates, and the change is written back as a delta (`replace`), so an op
that changes nothing changes nothing to the bit, and a sparse autoencoder's error term is kept exactly. A fit
trains an instance's `trains` tensors; its objective may name a featurizer's scalar as `<featurizer>.<scalar>`
(a gate's `mask` is the mean of its soft mask; an sae's `reconstruction` and `l1` are over what the body's
encodes of it saw in that run of the body, which the instance keeps while a fit trains it). Its math runs on
the value's device and dtype, with autocast off: a model served in bfloat16 under autocast leaves a float32
featurizer's float32 math alone.

A bundle is a safetensors file: an instance's `saves` tensors (the first laid out `[width, ...]`) and a header
saying what made them: the kind and its `header` fields, the model, the site it was used at (`component`,
`layer`), its `width` and the document's name. Both a `pca` op's value and a fit's trained featurizer are
saved as one. A document that loads one is checked against it key by key: the tensors and the kind, its
fields and the model when the plan compiles, the site at every use, and `width` against the model's size
before any forward. A file is clab's when its header's `format` is `clab/...`; one that carries clab's header
keys under another format is refused. Any other file is a published one, its kind's to read or refuse: an
`sae` reads one (SAELens, Gemma Scope), whose shapes alone are checked, against each other and the site's
width: nothing says what model or site it was made at, so neither is checked.

Each kind is one class, in a module of its own, registered under its name in lower case. It declares as class
attributes what its bundle holds (`saves`), what a fit trains (`trains`), the axis its coordinates are on
(`axis`), the fields its bundle's header records (`header`), the fields one drawn without a `file_path` needs
(`drawn`) and the scalars a fit's objective may name (`scalars`); its constructor makes an instance. Its modes
are the methods of the same names, `encode(h)` and `apply(h, ...)`, a kind defining only those it has; the
rest is the protocol `Kind` declares, with a default for what a kind need not have.

### `subspace`

- `k: int or null = None`
- `parametrization: one of 'cayley' = 'cayley'`
- `seed: int or null = None`
- `file_path: str or null = None`

A rank-`k` subspace: the first `k` columns of a rotation `origin @ cayley(theta)`. `origin` is a
Haar-random orthogonal matrix drawn from `seed`, and `theta` (what a fit trains) starts at zero, so an
untrained subspace is a uniformly random one and each seed draws a different one. Its bundle holds the
`[width, k]` basis.

Modes: `encode` gives its coordinates, the last axis becoming features; `apply` gives its version of the value, in the value's own layout: `h` projected onto the subspace.

### `gate`

- `temperature: {start: float, end: float} or null = None`
- `file_path: str or null = None`

A mask over units, `theta` starting at +1 on every one: soft (σ(θ/T)) while a fit trains it, hard
(θ > 0) whenever it is scored. `temperature: {"start", "end"}` sets T, linearly over the fit's epochs
(default 1).

Modes: `encode` gives its coordinates, the last axis becoming features; `apply` gives its version of the value, in the value's own layout: `h` times the mask: soft while a fit trains it, hard when scored.

### `pca`

- `file_path: str`
- `k: int or null = None`

The top-`k` principal directions (`basis`) and the `mean` a `pca` op saved, loaded from its bundle; its
coordinates are centred on the mean.

Modes: `encode` gives its coordinates, the last axis becoming features; `apply` gives its version of the value, in the value's own layout: `h` projected onto the principal directions through the mean: `mean + (h - mean) B Bᵀ`.

### `sae`

- `latents: int or null = None`
- `file_path: str or null = None`
- `seed: int or null = None`
- `activation: one of 'relu', 'jumprelu', 'topk' = 'relu'`
- `k: int or null = None`
- `centered: bool = True`

A sparse autoencoder (`W_enc`, `b_enc`, `W_dec`, `b_dec`), loaded from its bundle, or with `latents` a
dictionary a fit trains: drawn from `seed`, `W_enc` `[width, latents]` standard normal over sqrt(width),
`W_dec` `[latents, width]` with unit-norm rows (kept unit-norm by a projection after each optimizer step),
both biases zero. Its coordinates are the latents `act(pre)`, `pre = (h - b_dec) @ W_enc + b_enc`, or
`h @ W_enc + b_enc` when not `centered` (Gemma Scope's are not), and a write keeps its error term exactly.
`activation` is `relu` (`relu(pre)`), `jumprelu` (`relu(pre) * (pre > threshold)`, with the `threshold` a
published file holds) or `topk` (the relu of the `k` largest of `pre` in each vector, every other latent
zero). Its `file_path` may name a published SAE, a safetensors file with no clab header holding `W_enc`,
`W_dec`, `b_enc`, `b_dec` and optionally `threshold`, as SAELens and Gemma Scope publish them: its shapes
are checked against each other and the site's width, nothing says what model it was trained on, and the
document states its `activation` and `centered`, which have no default for it. Its
scalars, over every vector the body's encodes of it saw in that run of the body: `reconstruction`, the
mean of ‖h − (z @ W_dec + b_dec)‖², and `l1`, the mean |z|.

Modes: `encode` gives its coordinates, the last axis becoming features; `apply` gives its version of the value, in the value's own layout: `h`'s reconstruction: the decoding of its latents, `z @ W_dec + b_dec`, without the error term.

### `linear`

- `classes: str`
- `file_path: str or null = None`

A probe, `h @ W + b` (both starting at zero), whose coordinates are its classes: the distinct values of
the `classes` column, sorted, which its bundle's header records. A metric scores them against a column of
those values, as it scores logits against a column of tokens. It has no way back into the value, so it is
read in mode `encode` and never written through.

Modes: `encode` gives its coordinates, the last axis becoming classes.

### `lora`

- `rank: int or null = None`
- `alpha: float or null = None`
- `seed: int or null = None`
- `file_path: str or null = None`

A low-rank adapter, `A` `[width, rank]` and `B` `[rank, width]` at scale `alpha / rank`: loaded from its
bundle (its rank and alpha from the bundle's header), or with `rank` and `alpha` one a fit trains, drawn
from `seed`: `A` standard normal over sqrt(width), `B` zero, so it starts as the identity exactly. It has
no coordinates, so its one mode is `apply`, and no edit runs in its space.

Modes: `apply`(with: Value or null = None) gives its version of the value, in the value's own layout: `h + (alpha/rank) (x A) B`: `x` is `h`, or `with` (a value at the same positions, from another site of the same forward: an o_proj adapter reads `attention_premix` and applies at `attention_output`), its axes after the positions flattened into the adapter's width. The addition lands on the live value.

## Names and scoping

Names are one flat namespace per scope: no dots, and no step also a dataset or a featurizer.

A reference is "thing, then member", split at the first dot: `counterfactual.v_cf` is step
`counterfactual`'s read `v_cf`; `mean` is an op step's value; `pairs.cf_answer` is a dataset's column; `rot`
is a declared featurizer and `mask.mask` its scalar; `fit.rot` is a fit's member. Values are produced in
document order and referenced only after they exist. A fit's body is a scope of its own: it sees every
value produced before the fit, and nothing leaves it except through `<fit>.<member>`. A named intervention
is a template, so the names inside it resolve where a step pulls it in. Under a sweep, a name means the
producer's point that agrees with the consumer's coordinates on the producer's axes. Every value with a
rows axis knows the dataset its rows are aligned to (a forward's input; an op's `of`, operands and
columns), and an op takes one dataset's rows.

## Sweeps

Every `{"sweep": [...]}` standing for a value, by document path, labelled by the last key of its path.

A sweep may stand for any value except under `description` and `model`, on a name, a kind, a dataset's
source, or a `file_path`. Two sweeps with one label are refused; one sweep reached from two places (a swept site
two steps use) is one axis, so its points zip rather than cross. A step that uses a swept thing, or
references a value that varies, becomes a list of points, one per combination of its axes, each a whole
step whose `at` gives its index on each axis; a step no sweep touches runs once. A saved value of a
swept step is a dict keyed by coordinate: the axis's value, or a tuple of them in axis order.

## Saves and the output

A run's output directory and back, and saved values as tables.

One file per save, named after it: `<name>.safetensors` when the value is a tensor or a dict of tensors (a
bundle; a ragged read's `{values, row, tok}`), `<name>.json` otherwise, tensors in it as nested lists. A swept
save holds one entry per point, keyed by its coordinate: `pos=-1` in safetensors, `"-1"` in JSON
(`layers=0,pos=-1` and `"0,-1"` over two axes), a dict's own keys after a `/`. A file is the value and
nothing else, except that a bundle a featurizer loads (the value of an op that declares one, `pca`, and a
fit's trained featurizer) carries the header that featurizer checks.

`manifest.json` is the compiled plan without the rows it read from files and without bundle tensors, its
`results` each replaced by `{file, step, dims, axes, shape, dtype}`: that is how a result links back to the
step that made it. It records the document's path relative to the corpus root, and each dataset's `n_rows`. `shape` and `dtype` follow the value's structure (per key, per point).
The plan's `run` holds how each input tokenized, what each generate step's rows generated, and which
position (an index into the row's prompt tokens, then its generated ones) every read and write resolved to
per row, which
`table` uses to label positions. Values are never in the manifest.

The saved values `names` as rows, joined wide on their shared axes, one column per name.

A value with a rows axis gives a row per example and token: `at` (its point's coordinates; a value whose step is
not swept has no `at`), `row`, `example_id` when the dataset has one, `layer` under `layers: "all"`, the token
axes with their tokens (`pos`/`pos_token`, the position a read resolved to: the index into the row's prompt
tokens, then in a generation its generated ones, with the forward `call` holding it for a read in a generation;
`key`/`key_token` on an attention pattern), the dataset columns the step used (`columns=` to choose), and
`value` last: the element, or the remaining axes as nested lists. A ragged value gives a row per entry. A row a
read beyond the prefill did not reach gives one row, `alignment_missing` true, with
no value. A value with no rows axis gives a row per element with its axis indices.
