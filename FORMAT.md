# The clab format

Generated by `clab describe --markdown` from the code; a test fails when this file and the code disagree. A document is one JSON object that declares a complete experiment; `clab run DOC` runs it.

## Root keys

| key | holds |
| --- | --- |
| `description` | what the experiment is, in prose |
| `model` | the checkpoint, and how to load it |
| `data` | each dataset by name |
| `sites` | named locations, referenced by `site` |
| `interventions` | named bundles of writes and reads, pulled into a step by `interventions` |
| `featurizers` | named spaces a read or write happens in |
| `steps` | what runs, in order; its last entry `saves` names what comes home |

### `model`

- `key: str`
- `revision: str`
- `dtype: one of 'fp32', 'fp16', 'bf16' = 'fp32'`
- `attn_implementation: one of 'eager', 'sdpa' or null = None`

The pinned checkpoint. The attention interior needs `attn_implementation: "eager"`.

### `data.<name>`

- `path: str or null = None`
- `rows: list or null = None`

`path` is `data/<path>.json` under the corpus root, `#<split>` keeping the rows of that split; or inline `rows`.

### `sites.<name>`, or a `site` inline

- `component: str`
- `layers: int or one of 'all' or null = None`
- `heads: list of int or null = None`
- `units: list of int or null = None`

A component, narrowed: `layers` (an int, or `"all"`: one value, layer axis first) on a block's
component; at most one of `heads` and `units`, as the component allows.

### `interventions.<name>`

A bundle of `writes` and `reads` (each by name), pulled into a step by `"interventions": "<name>"` or a list of names. A thing declared at the root (`sites`, `interventions`, `featurizers`) is referenced by name, or the same thing is written inline where it is used once.

### A write or a read

- `site: str or dict`
- `pos: int or dict`
- `ops: list or null = None`

A write or a read: the `site` it lands on (a declared name, or one inline), the positions `pos` names
there, and the `ops` it runs on that selection.

Several writes at one site compose in listed order on one copy of the value; a read at a written site observes the writes.

## Step kinds

Each entry of `steps` is `{"kind": <kind>, ...fields}`; the last entry may be `saves`.

### `forward`

- `input: str`
- `writes: dict or null = None`
- `reads: dict or null = None`
- `interventions: str or list of str or null = None`

One forward over every row of a dataset input. `input` is `<dataset>.<column>` or
`<dataset>.<column>[i]`; `writes` land where they name before anything later reads them; each read binds
`<step>.<read>`; `interventions` pulls named bundles of writes and reads in, in listed order, before the
step's own.

Rows run in consecutive batches of the run's batch size, each padded on the left to the input's longest
row, with position ids that count real tokens. A row's numbers then do not depend on which rows share its
batch, but they do depend on the batch's shape: a trailing partial batch is a smaller matrix, and can
differ in the last bits. Results reproduce to the bit at a fixed batch size.

### `generate`

- `input: str`
- `max_new_tokens: int`
- `min_new_tokens: int = 0`
- `do_sample: bool = False`
- `writes: dict or null = None`
- `reads: dict or null = None`
- `interventions: str or list of str or null = None`

Generation from every row of a dataset input. Writes land on the prompt; reads in the `generated` frame
read decode steps. The step's own value is the new token ids, `[rows, new]`.

### `op`

- `op: str`
- `of: str`
- `...the op's arguments`

An op over a value earlier steps produced: `of` names it, and the op's arguments sit beside it (see Ops).
The step's value is the op's result.

### `fit`

- `train: list of str`
- `objective: dict`
- `epochs: int`
- `batch_size: int`
- `seed: int`
- `optimizer: dict`
- `steps: dict`
- `early_stop: dict or null = None`
- `eval: dict or null = None`

Train the featurizers `train` names. Each epoch runs the body `steps` over minibatches of `batch_size`
rows and minimizes the weighted sum `objective` (`{term: weight}`; a term is a body op, averaged, or a
trained featurizer's scalar, `<featurizer>.<scalar>`). Inside the body a trained featurizer's name and
`<fit>.<featurizer>` are the one being trained. Afterwards `<fit>.<featurizer>` is the trained one,
`<fit>.<op>` a body op under `eval`, `<fit>.<step>.<read>` a body read, and `<fit>.history.<op>` the
body op's mean per epoch.

### `fit` blocks

`optimizer`:

- `name: one of 'adamw', 'adam', 'sgd'`
- `lr: float`
- `weight_decay: float = 0.0`

The fit's optimizer, over the trained featurizers' parameters only.

`early_stop`:

- `metric: str`
- `mode: one of 'max', 'min'`
- `patience: int`

End the fit after `patience` epochs without improvement of a body op's mean, scored on the training data.

`eval`:

- `data: dict`

After the fit, run the body once with each dataset `data` maps read as the other (`{"train": "test"}`).

## Ops

The one computation vocabulary: every op is a plain function over tensors.

An op runs in three places, always as the same function:

- as a step, `{"kind": "op", "op": "mean", "of": "harvest.acts"}`, over a
  value earlier steps produced;
- inside a read, `"ops": [...]`, on the gathered selection before its name
  binds;
- inside a write, `"ops": [...]`, on the live selection at the site; what the
  last op returns is written back.

`@op(...)` registers the function under its own name and declares its axis
behaviour: the axes the input must carry (`needs`), the axes it removes
(`removes`: a tuple, or the name of the argument that lists them) and the axes
it appends (`adds`). Compile reads these to lay out every value, and refuses an
op inside a read or write that aggregates over `rows`: there it sees one batch,
so it must act per example (make it a step after the forward).

A parameter's annotation says how a document fills it: `Value` is a named
value or a number, `Tokens` a dataset column of one token per row (resolved
through the value's own vocabulary, inside the run), `Featurizer` a
featurizer's name; anything else is a literal. Three parameters are filled by
the run, never by a document: `engine`, `original` (inside a write, the value
at the site before its writes) and `dims` (the axis names of `of`). A trailing
underscore is dropped from a parameter's document spelling (`with_` is
`"with"`). Inside a read or write, `featurizer` and `features` are arguments of
every op: the op runs on the value's coordinates in that featurizer's space
(on the `features` given) and the change is written back.

| op | arguments | axes | what |
| --- | --- | --- | --- |
| `swap` | `with: Value` | keeps the layout | Replace the value with `with`, broadcast over its rows and positions. |
| `add` | `with: Value`, `scale: float = 1.0` | keeps the layout | `of + scale * with`. |
| `sub` | `with: Value` | keeps the layout | `of - with`. |
| `scale` | `factor: float` | keeps the layout | `of * factor`. |
| `renormalize` | — | keeps the layout | Each vector rescaled to the norm of `original`'s; inside a write, the value before the site's writes. |
| `normalize` | — | keeps the layout | Each vector divided by its norm. |
| `project_out` | `direction: Value` | keeps the layout | Each vector less its component along `direction`. |
| `readout` | — | needs hidden_size; removes hidden_size; adds vocab_size | The model's own unembedding of a residual-stream value (the logit lens). |
| `encode` | `featurizer: Featurizer` | needs hidden_size; removes hidden_size; adds features | The value's coordinates in `featurizer`'s space. |
| `mean` | `over: list of str or null = None` | removes the axes `over` names | The mean over the axes `over` names; by default every axis but the feature axes. |
| `pca` | `k: int` | needs hidden_size; removes layers, rows, entries, pos; adds k | The top-`k` principal directions and the mean, as a bundle for a `pca` featurizer. |
| `match` | `expected: Tokens`, `token_form: one of 'spaced', 'bare' = 'spaced'` | needs vocab_size; removes vocab_size | 1 where the most likely token is `expected`, else 0. |
| `logit_diff` | `a: Tokens`, `b: Tokens`, `token_form: one of 'spaced', 'bare' = 'spaced'` | needs vocab_size; removes vocab_size | The logit of `a` less the logit of `b`. |
| `token_prob` | `token: Tokens`, `token_form: one of 'spaced', 'bare' = 'spaced'` | needs vocab_size; removes vocab_size | The probability of `token`. |
| `token_logit` | `token: Tokens`, `token_form: one of 'spaced', 'bare' = 'spaced'` | needs vocab_size; removes vocab_size | The logit of `token`. |
| `cross_entropy` | `target: Tokens`, `token_form: one of 'spaced', 'bare' = 'spaced'` | needs vocab_size; removes vocab_size | The negative log-probability of `target`, in nats. |
| `kl` | `against: Value` | needs vocab_size; removes vocab_size | KL(of ‖ against) between the two next-token distributions, in nats. |
| `js` | `against: Value` | needs vocab_size; removes vocab_size | The Jensen–Shannon divergence between the two distributions, in nats (at most log 2). |
| `top_k` | `k: int` | needs vocab_size; removes vocab_size; adds k | The `k` most likely tokens and their probabilities, decoded. |

## Components

The locations clab allows: what each component means, its layout, and what narrows it.

A component's name is nnterp's name for the same value, and its `dims` are
nnterp's layout of it (`batch` first, the token axis named `seq`, or `query` on
an attention pattern). `per_layer` says it is a block's value, so a site names
its `layers`. `narrow` maps each narrowing key a site may carry to the axis it indexes.
`stream` marks the residual-stream values `readout` may project.

A selection of a component (what a read binds, and what a write's ops see) is
laid out `(rows, pos, *the remaining axes in order)`: a `layers` axis comes
first under `layers: "all"`, and ragged positions give `entries` (one per
token) in place of `rows` and `pos`. How an engine reaches a component is that
engine's business; the name says only what the value is.

| component | dims | narrowed by | meaning |
| --- | --- | --- | --- |
| `token_embeddings` | batch, seq, hidden_size | units | the embedding module's output |
| `layer_input` | batch, seq, hidden_size | layers, units | the residual stream entering block i |
| `attention_norm_output` | batch, seq, hidden_size | layers, units | the normed stream the attention is called with |
| `attention_queries` | batch, num_heads, seq, qk_head_dim | layers, heads | queries after projection, head split and RoPE |
| `attention_keys` | batch, num_kv_heads, seq, qk_head_dim | layers, heads | keys, before repeat_kv |
| `attention_values` | batch, num_kv_heads, seq, head_dim | layers, heads | values, before repeat_kv |
| `attention_scores` | batch, num_heads, query, key | layers, heads | scaled, masked scores entering the softmax |
| `attention_probabilities` | batch, num_heads, query, key | layers, heads | the pattern the values are mixed with |
| `attention_head_outputs` | batch, seq, num_heads, head_dim | layers, heads | each head's output, before the output projection |
| `attention_premix` | batch, seq, num_heads, head_dim | layers, heads | every head's result as the output projection takes it |
| `attention_output` | batch, seq, hidden_size | layers, units | what attention adds to the stream |
| `layer_mid` | batch, seq, hidden_size | layers, units | the stream between the sublayers |
| `mlp_norm_output` | batch, seq, hidden_size | layers, units | the normed stream entering the MLP |
| `mlp_input` | batch, seq, hidden_size | layers, units | what the MLP is called with |
| `mlp_activation` | batch, seq, intermediate_size | layers, units | act(gate_proj x) on a gated MLP, act(up_proj x) on a plain one |
| `mlp_neurons` | batch, seq, intermediate_size | layers, units | what the down projection sums |
| `mlp_output` | batch, seq, hidden_size | layers, units | what the MLP adds to the stream |
| `layer_output` | batch, seq, hidden_size | layers, units | the residual stream leaving block i |
| `final_norm_output` | batch, seq, hidden_size | units | the final norm's output, what the head projects |
| `lm_head_output` | batch, seq, vocab_size | units | the head's own projection |
| `logits` | batch, seq, vocab_size | units | what the model returns, after any softcap |

## Featurizer kinds

Featurizer kinds: each is a function from its document fields to an instance, a dict of tensors.

A featurizer is a space a read or write happens in. Its kind's signature is
its contract: the document fields it takes, with `width` (the feature width
of the sites it is used at) supplied by the run. An instance is built where
the model is, at first use: drawn from its `seed` (else the fit's seed, else
0), or from the bundle a `file_path` names, which compile reads into the plan
and checks key by key against the document. A fit's objective may name a
featurizer's scalar as `<featurizer>.<scalar>`: a gate's `mask` is the mean of
its soft mask.

### `subspace`

- `k: int`
- `parametrization: one of 'cayley' = 'cayley'`
- `seed: int or null = None`
- `file_path: str or null = None`

A rank-`k` subspace: a Haar-random rotation, Cayley-parametrized, its first `k` columns the basis.

### `gate`

- `temperature: dict or null = None`

A mask over units, soft (σ(θ/T)) while a fit trains it and hard (θ > 0) when scored.

`temperature: {"start", "end"}` anneals T linearly over the fit's epochs.

### `pca`

- `k: int`
- `file_path: str`

The top-`k` principal directions and mean a `pca` op saved, loaded from its bundle.

### `sae`

- `file_path: str`

A sparse autoencoder with its error term kept exactly, loaded from its bundle.

### `linear`

- `classes: str`

A probe, `h @ W + b`; its output axis is the distinct values of the `classes` column, sorted.

## Positions

`pos` names token positions within a scope.

```
pos := int                                    # the one shorthand: {"index": int}
     | {"frame"?: "prompt" | "generated",     # default "prompt"
        "scope"?: {"variable": column} | {"segment": "role[n]" | "role" | "eos"},
        exactly one of "index": int | "span": [start, stop] | "all": true}
```

Indices count the scope's tokens and may be negative (from its end); a
span is half-open. The prompt's tokens are the row's tokens that are not
special (BOS is never one) and not padding. `variable` scopes to the row's
own text of that column, located in its input; `segment` to a chat turn
(`user[1]` is the second user message) or, in the generated frame, to where
the row stopped (`eos`). The generated frame counts decode steps: index
*k* is the forward that chose new token *k*, read at its last position.
A turn has no meaning in the generated frame, nor `eos` in the prompt.

Every pos compiles to `{"frame", "scope", "start", "stop"}`, a slice of
the scope's tokens.

## Names and scoping

Names are one flat namespace per scope: no dots, and no name both a step and a dataset or featurizer.

A reference is "thing, then member", split at the first dot: `counterfactual.v_cf` is step
`counterfactual`'s read `v_cf`; `mean` is an op step's value; `pairs.cf_answer` is a dataset's column;
`rot` is a declared featurizer and `mask.mask` its scalar; `fit.rot` is a fit's member. Values are
produced in document order and referenced only after they exist. A fit's body is a scope of its own: it
sees every value produced before the fit, and nothing leaves it except through `<fit>.<member>`. A named
intervention is a template, so the names inside it resolve where a step pulls it in. Under a sweep, a
name means the producer's point that agrees with the consumer's coordinates on the producer's axes.

## Sweeps

Every `{"sweep": [...]}` standing for a value, by document path, labelled by the last key of its path.

A sweep may stand for any value except under `description` and `model`, on a name, a kind, a data `path`
or a `file_path`. Two sweeps with one label are refused; one sweep reached from two places (a swept site
two steps use) is one axis, so its points zip rather than cross. A step that uses a swept thing, or
references a value that varies, becomes a list of points, one per combination of its axes, each a whole
step whose `at` gives its index on each axis; a step no sweep touches runs once. A saved value of a point
lands under one `<label>=<value>/` directory per axis.

## Saves

`saves` names the values that come home, `{name: file}` or `[names]`, each at the path its file gives
under the output directory (`.json` a table, `.safetensors` tensors); a list entry is saved as
`<name>.json` when it is an op's value, else `<name>.safetensors`. Every other value is gone when the
run ends. Saves are declared only at the root of `steps`.

## A worked document

`documents/patching.json`:

```json

Two forwards over the same pairs, and two metrics of the second: four steps. The head is a site written in place, because nothing else names it.",
  "model": {
    "key": "hf-internal-testing/tiny-random-LlamaForCausalLM",
    "revision": "9fb191250dd56d0ba7ec9785a025ed29c03d5998",
    "dtype": "fp32"
  },
  "data": {"pairs": {"path": "weekdays/train"}},
  "sites": {"target": {"component": "layer_output", "layers": 0}},
  "steps": {
    "counterfactual": {
      "kind": "forward",
      "input": "pairs.counterfactual_inputs[0]",
      "reads": {"v_cf": {"site": "target", "pos": -1}}
    },
    "patched": {
      "kind": "forward",
      "input": "pairs.input",
      "writes": {
        "patch": {"site": "target", "pos": -1, "ops": [{"op": "swap", "with": "counterfactual.v_cf"}]}
      },
      "reads": {"logits": {"site": {"component": "lm_head_output"}, "pos": -1}}
```
