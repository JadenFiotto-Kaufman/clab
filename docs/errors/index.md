# Errors Index

Up: [docs/index.md](../index.md) — all sections.

Find the message you saw. If the run finished, nothing was refused and the numbers look wrong, use [symptom-index.md](symptom-index.md) instead.

`clab run` prints a refusal as `clab: <where>: <what>`. A `<where>` that is a document path (`steps.patched.interventions.patch.pos`, `data.pairs.take`, `featurizers.rot.file_path`) came from reading or compiling the document, before any model loaded; the exceptions are `model.<key>`, which the engine raises as it loads the checkpoint, and `data.<name>: … digest differs`, which the run raises. A refusal that names a run option (`device 'gpu': …`, `batch_size 0: …`, `tp 2 shards …`) is the command line's or the engine loader's, before anything loads. A step's name without `steps.` (`patched.patch`, `iia`) came from preflight: the model loaded and no forward ran; `steps.<name>: out of CUDA memory …` came from the run itself. Inside a fit's body it starts with the fit (`fit.counterfactual.v_cf`), and in an eval with its eval step (`fit.held_out.adapted.adapt`). [plan-lifecycle.md](../concepts/plan-lifecycle.md) says what each stage checks. In Python, Plan and compile raise `PlanError` (`clab/plan.py`), a `ValueError`; preflight raises `ValueError`.

The messages below drop the `<where>:` prefix. `<x>` stands for a name or value from your document.

## Errors that are not clab's

A malformed command line (an unknown flag, a missing argument, a value outside a flag's choices) gets argparse's usage message and exit status 2, not a `clab:` line: `clab describe: error: argument what: invalid choice: 'bogus' (choose from …)`. An engine no one registered is a `clab:` line, `clab: unknown engine 'bogus'; valid: nnterp, hooks, ndif, vllm` ([cli.md](../reference/cli.md)).

Under `--engine ndif`, preflight and the run happen on the server. With `-o remote=local`, nnsight's local simulation of that trip, `clab run` prints the same `clab:` line as under nnterp; [engines.md](../usage/engines.md) covers a real server.
